## Typed rule and error precedence

The reference checks `!signer?.key_id || !signer?.private_key` before canonicalization or crypto and raises `integrity_signer_required`, message `a key_id and Ed25519 private_key are required`, path `$`. Rust takes `&dyn ArtifactSigner`; `key_id()` returns `&str`, and `sign_ed25519()` supplies the signature. Missing signer/private material is therefore a typed-caller boundary, with no representable missing-signer runtime input. An empty string is representable and receives exactly the reference's producer refusal before malformed-body errors or signing callbacks. This does not validate private-key possession or authenticate runtime configuration.

The Rust helper reads `key_id()` once, checks that value, and uses it in the result. The trait promises no callback purity. A second read could return an unchecked different id even after the first value passed the guard. This capture rule is Rust callback consistency, not a claim of parity for arbitrary JavaScript getter objects; ordinary immutable Node signer inputs retain the same behavior. Neither the reference validator nor the approved profile text is changed by #104.
